# 実装計画

## 機能選定

### 設計方針の転換

- CLIは「SNAGS専用ツール」ではなく、**汎用gistフロントエンド**として機能する
  - `frontmatter.md`はSNAGS独自機能(title上書き、tag、category)を使うための**オプション**情報であり、必須ではない
  - `frontmatter.md`が存在しないgistも通常通り扱える。title = 元ファイル名、tag/category = 空、として扱う
  - 既存の全gist(SNAGS由来かどうかを問わない)が管理対象になる

### ローカル作業ディレクトリ中心の設計

現行CLIの課題(対話式フローが一括処理のため、途中保存・複数ファイル追加・タイトル変更ができない)を解消するため、「作成フェーズ」と「pushフェーズ」を分離する。

- 1 tips = 1 ローカル作業ディレクトリ
- ディレクトリ内は自由に編集・ファイル追加・削除が可能(CLIを経由しない直接編集も許容する)
- CLIは、そのディレクトリに対する操作(cdせずに行える参照・編集などの操作)を提供する薄いラッパーとして機能する
- ディレクトリ内は**サブフォルダ禁止・フラット構成のみ**(GitHub Gistがフォルダ階層を持てない制約に合わせる)
- フロントマター用ファイルは`frontmatter.md`に固定(予約名)。存在しない場合は上記の通りフォールバックする

### slug(ディレクトリ名/gist識別子)

- `autoSlug` configで生成方式を切り替え可能にする
  - `true`: UUID等、言語非依存の自動生成(タイトルの言語がどれであっても対応可能なため)
  - `false`: ユーザーが英語で手動入力
- タイトルは言語を問わず自由入力とし、frontmatterに保持する。`list`表示では常にtitleを表示し、slugは内部識別子として隠す(slugがUUIDでもURL/内部処理にのみ影響し、表示上の実害はないと判断)

### category

- `frontmatter.md`に含める項目は**title, categoryの2種のみ**とする(tagは採用しない)
- categoryの値は事前定義(config allowlist)を要求しない。**フリー入力**とする
- categoryの履歴一覧は、専用ファイルを新設せず、メイン設定ファイル(`conf`管理)の1キー(例: `categories: string[]`)として保持する
- 新規category追加時は、既存の履歴一覧と**大文字小文字を無視して**一致するか判定し、一致すれば新規追加せず既存のものを使う(重複登録防止)
- CLIがfrontmatterを読み込む処理(list表示、sync、edit終了時)のたびに、そのcategory値をconfigの履歴一覧と突き合わせ、未知の値であれば自動追記する
  - `create`経由、`edit`経由、CLIを介さない手動編集のいずれであっても、次にCLIがそのファイルを読んだタイミングで一律に反映される
- `create`時にfrontmatterを生成するかどうかは、config側のデフォルト値 + `--no-frontmatter`等のオプション引数の両方で制御可能にする

### 同期モデル(remoteを正とする)

GitHubと同様、**remote(gist)を正**とする同期モデルを採用する。

- `edit`実行時の分岐:
  1. ローカルに未sync変更が**ない**、かつremoteが新しい → 自動でpullしてから編集
  2. ローカルに未sync変更が**ある**、かつremoteも更新されている(コンフリクト) → 編集を拒否し警告。ユーザーは先に`sync`するか手動でコンフリクトを解消する
  3. ローカルに未sync変更があるが、remoteは変わっていない → そのまま編集続行
- リモートの更新有無は、gistの`updated_at`等の軽量な問い合わせで判定し、変更がある場合のみフル同期する(通信コストを抑える)
- `sync`(push)実行前に、差分プレビューを表示する(差分計算は`diff`ライブラリの`diffLines`、色付けは`picocolors`を使用。詳細は技術選定を参照)

### コマンド仕様表

対象を1件選ぶ必要があるコマンド(`edit`/`delete`)は、位置引数を持たず**常に対話式(fuzzy検索)**で選択する。

| コマンド | 動作概要                                                                                                              | 対象指定           | オプション                                                 | 主なclack/promptsコンポーネント                                                            |
| -------- | --------------------------------------------------------------------------------------------------------------------- | ------------------ | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `create` | title入力→slug決定(autoSlug設定に応じ自動/手動)→category選択→frontmatter生成有無の分岐→ディレクトリ作成→`$EDITOR`起動 | -                  | `--no-frontmatter` / `--frontmatter`(config既定値の上書き) | `text`(title, 手動slug), `select`+`text`(category選択+新規フリー入力)                      |
| `edit`   | fuzzy検索で対象選択→remote同期3分岐判定→`$EDITOR`起動→保存時にcategory自動追記フック実行                              | 常に対話式選択     | なし                                                       | `autocomplete`/`select`(title fuzzy+category絞り込み), `confirm`(コンフリクト時の警告確認) |
| `list`   | 全tips一覧を`cli-table3`で表示                                                                                        | フィルタで絞り込み | `--category`, `--filter <keyword>`                         | 基本非対話(標準出力のみ)                                                                   |
| `delete` | fuzzy検索で対象選択→確認→ローカル/remote両方削除                                                                      | 常に対話式選択     | なし                                                       | `autocomplete`/`select`(対象選択), `confirm`(削除確認)                                     |
| `sync`   | 未sync変更のある**全tips**を差分プレビュー表示の上でpush                                                              | 全件一括           | なし                                                       | `confirm`(差分プレビュー後のpush確認)                                                      |
| `status` | ローカル/remoteの同期差分(未push/未sync編集/未pull)を一覧表示                                                         | -                  | なし                                                       | 非対話(標準出力のみ)                                                                       |
| `doctor` | 整合性チェック実行→問題一覧表示→自動修復可能なものはY/n確認の上で修復(下記参照)                                       | 全件チェック       | なし                                                       | `confirm`(個別修復確認)                                                                    |
| `init`   | gh auth確認→config雛形生成→既存全gist取得→ローカル復元→categoryをfrontmatterから初期構築                              | -                  | なし                                                       | `spinner`(進捗表示), 未認証時は案内メッセージ                                              |
| `config` | 引数指定時はkey-value直接操作、引数なし時は対話メニュー                                                               | -                  | `set <key> <value>`, `get <key>`, `list`                   | `select`(対話メニュー), 項目に応じ`text`/`confirm`/`select`                                |

### ファイル構成

| ファイル                                                          | 配置                 | gistへpushされるか | 内容                                                              |
| ----------------------------------------------------------------- | -------------------- | ------------------ | ----------------------------------------------------------------- |
| メイン設定ファイル(`conf`管理、例: `~/.config/snags/config.json`) | グローバル1ファイル  | されない           | `autoSlug`, frontmatter生成デフォルト, category履歴キャッシュ, 等 |
| `frontmatter.md`                                                  | 各tipsディレクトリ内 | **される**         | title, category                                                   |
| `.snags-meta.json`                                                | 各tipsディレクトリ内 | **されない**       | 対応するgist ID, 最終同期時刻/差分検知用情報                      |
| その他任意ファイル(コードスニペット等)                            | 各tipsディレクトリ内 | **される**         | ユーザーが自由に追加する本体ファイル群                            |

### doctorの対象範囲

データ損失リスクの有無で「自動修復するか/検出のみに留めるか」を分ける。

- 壊れた`frontmatter.md`(YAMLパースエラー) → 自動修復しない。`frontmatter.md.bak`へ退避し、`$EDITOR`での手動修正を促す(誤ったデータでの自動補完は危険なため)
- 禁止文字を含むファイル名 → 警告 + Y/n確認でのリネームを提案(自動修復可、リスクが低いため)
- 禁止されたサブフォルダの存在 → 検出・警告のみ(機械的なフラット化は名前衝突や意図しない構成変更のリスクがあるため自動修復しない)

(`frontmatter.md`自体の欠落は、設計転換によりエラー扱いではなくなったため対象外)

### UI

- gum(bashモジュール)への依存を廃止する
  - 原因: ターミナル幅とCJKワイド文字数の兼ね合いで表示崩れが発生していた
- Node.jsネイティブライブラリで自前実装する(技術選定を参照)

### パッケージング

- `package.json`の`bin`フィールド + リンクにより、`pnpm snags ...`ではなく`snags ...`でグローバル実行可能にする

## 技術選定

| 領域              | 採用                                                    | 理由                                                                                                                                                                                                                 |
| ----------------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GitHub通信        | `gh auth token`でトークン取得 → Octokit(REST API)で通信 | PAT発行をユーザーに求めずに済み(gh CLIの認証に相乗り)、かつサブプロセス起動のオーバーヘッドや型安全性の欠如といったシェルアウト方式の欠点を回避できるハイブリッド案                                                  |
| CLIフレームワーク | `citty`                                                 | サブコマンド構成がデフォルトで組み込まれておりTypeScript志向                                                                                                                                                         |
| 対話UI            | `@clack/prompts`                                        | 使用実績があり採用                                                                                                                                                                                                   |
| frontmatterパース | `gray-matter`                                           | frontmatterのパース/生成に特化。壊れたYAMLは例外を投げるため`doctor`のエラー検出とも相性が良い                                                                                                                       |
| テーブル表示      | `cli-table3`                                            | CLIは基本英語表示でタイトルのみ多言語になる可能性がある程度のため、まずは既製ライブラリで対応し、表示崩れが大きい場合に自前実装を再検討する                                                                          |
| config管理        | `conf`                                                  | 保存場所解決・デフォルト値・スキーマバリデーションを任せられ実装コストを下げられる                                                                                                                                   |
| ログ              | `consola`                                               | (`rebuild-cli.md`記載の既定方針)                                                                                                                                                                                     |
| UUID生成          | Node.js標準の`crypto.randomUUID()`                      | 追加ライブラリ不要                                                                                                                                                                                                   |
| 差分計算          | `diff`(`diffLines`)                                     | 行単位差分計算の業界標準ライブラリ                                                                                                                                                                                   |
| 色付け            | `picocolors`                                            | 軽量・依存ゼロ。`consola`はログレベルの意味的な色付け、`picocolors`は差分表示等の任意文字列への低レベルな色付けを担当する、と役割を分ける                                                                            |
| 構造検証          | `zod`                                                   | `frontmatter.md`/`.snags-meta.json`のパース結果に対する構造検証(型不正の検出)に使用。YAML構文エラーはgray-matter、構造的な不正はzodが検出する分担。slug等の単純な文字種チェックは正規表現で済ませ、zodは持ち出さない |
